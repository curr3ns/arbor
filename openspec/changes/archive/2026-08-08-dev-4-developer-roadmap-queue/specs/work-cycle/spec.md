## REMOVED Requirements

### Requirement: Change scope is limited to the work-cycle skill

**Reason**: This requirement was the blast-radius fence for the previous change (`dev-3-workcycle-roadmap-close`), which taught `arbor-auto-work` to close the roadmap item it just built. It states that `arbor-auto-developer` SHALL NOT be created, modified, moved, or deleted — a rule that was correct for that change and is directly contradicted by this one, whose entire subject is rewriting `.claude/skills/arbor-auto-developer/SKILL.md`. Leaving it in the live spec set would leave `work-cycle` asserting a constraint the repo has deliberately moved past, exactly as `dev-3` found with the equivalent fence left behind by `dev-2`, and `dev-2` before it with `dev-1`'s.

**Migration**: None required — no behavior changes and no file under `.claude/skills/arbor-auto-work/` is touched by this change. Scope fencing for the current change lives in the `roadmap-queue` capability, under **Change scope is limited to the auto-developer skill**, which limits this change to `.claude/skills/arbor-auto-developer/SKILL.md` and preserves the same protections in the opposite direction — for `arbor-auto-work`, `arbor-auto-roadmap`, `arbor-opsx-auto`, `arbor-project-scaffold`, `docs/roadmaps/archive/`, and `docs/roadmaps/roadmap-native-workcycles.md`. Every other requirement in `work-cycle` is unaffected, including the optional `roadmap:` token, its step-0 strip and validation, the three hard-error cases, the pre-commit flip, the same-commit archival with `git mv`, the commit-body bullets, and the gate and environment-blocked contracts — all of which `arbor-auto-developer` now depends on as the consumer of the token it dispatches with.
